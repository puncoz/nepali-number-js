# nepali-number — AI/LLM Agent Development Guide

This document is the authoritative reference for AI agents and contributors working on this package. Read it fully before writing any code or proposing changes.

---

## Package Identity

- **NPM name**: `nepali-number`
- **Version**: 2.0.0 (semver, breaking changes increment major)
- **Purpose**: Zero-dependency TypeScript library for Nepali number conversion, formatting, word representation, and currency — targeting Node.js, browsers, and bundlers simultaneously.
- **Public API surface**: ~20 named exports across 5 domains, all re-exported from `src/nepali-number.ts`.

---

## Non-Negotiable Constraints

Before writing a single line, internalize these — violating them will cause build or type-check failures:

1. **Zero runtime dependencies.** No `import` of any third-party package in `src/`. Dev dependencies only.
2. **No environment-specific APIs.** No `window`, `document`, `process`, `fs`, `Buffer`, or any DOM/Node global in library modules.
3. **Strict TypeScript.** All strict flags are on (see `tsconfig.json`). `noUnusedLocals`, `noUnusedParameters`, `noUncheckedIndexedAccess`, `isolatedDeclarations` are all enabled. Do not add `// @ts-ignore` or cast to `any`.
4. **Pure functions only.** No module-level side effects, no mutable module state, no class instances in the public API.
5. **No throwing.** Return safe defaults instead of throwing exceptions. If a function cannot produce a meaningful result, return `""`, `0`, `NaN`, or `null` as appropriate and document the behavior in JSDoc.
6. **Explicit return types on all exported functions.** Required by `isolatedDeclarations`.
7. **Unicode-safe.** Never use `.length`, `.slice()`, or `.charAt()` on strings containing Nepali (Devanagari) characters without awareness of Unicode code points. Use `Array.from()` or regex with Unicode flags when iterating over characters.

## Public API Reference

All functions below are exported from `src/nepali-number.ts` and available as named imports from the package.

### Conversion (`src/conversion/`)

| Function | Signature | Description |
|---|---|---|
| `toNepali` | `(input: string \| number) => string` | Replace English digits (0-9) with Nepali digits (०-९), preserving all other characters |
| `toEnglish` | `(input: string \| number) => string` | Replace Nepali digits with English digits |
| `parseNepaliNumber` | `(input: string) => number` | Parse a Nepali-digit string to a JS number |
| `convert` | `(input: string \| number, toNepaliDigits: boolean) => string` | Direction-switching wrapper |

### Formatting (`src/formatting/`)

| Function | Signature | Description |
|---|---|---|
| `formatNepaliNumber` | `(input: string \| number, options?: FormatOptions) => string` | Full formatter: Nepali digits, Indian commas (lakh/crore), decimal precision, currency symbol |
| `addNepaliCommas` | `(input: string \| number) => string` | Apply Indian numbering commas only (no other transforms) |
| `removeFormatting` | `(input: string) => string` | Strip commas and currency symbols, return raw number string |

**`FormatOptions`** (from `src/formatting/types.ts`):
```ts
interface FormatOptions {
  useNepaliDigits?: boolean   // default false
  addCommas?: boolean         // default false; uses Indian format (1,00,000)
  precision?: number          // decimal places
  trimZero?: boolean          // trim trailing zeros after decimal
  currency?: boolean          // prepend currencySymbol
  currencySymbol?: string     // default "रू"
}
```

### Words (`src/words/`)

| Function | Signature | Description |
|---|---|---|
| `toNepaliWords` | `(input: string \| number) => string` | Number to Nepali words: `123` → `"एक सय तेईस"` |
| `toEnglishWords` | `(input: string \| number) => string` | Number to English words: `123` → `"One Hundred Twenty Three"` |
| `toNepaliOrdinal` | `(input: string \| number) => string` | Number to Nepali ordinal: `1` → `"पहिलो"`, `5` → `"पाँचौं"` |
| `toDecimalWord` | `(input: string \| number) => string` | Abbreviated scale: `1_200_000` → `"१२ लाख"` |

### Currency (`src/currency/`)

| Function | Signature | Description |
|---|---|---|
| `toNepaliCurrency` | `(input: string \| number, options?: CurrencyOptions) => string` | Format amount with Nepali Rupee symbol |
| `toNepaliCurrencyWords` | `(input: string \| number, options?: CurrencyOptions) => string` | Express amount in Nepali words: `"दुई सय पचास रुपैयाँ"` |

**`CurrencyOptions`** (from `src/currency/types.ts`):
```ts
interface CurrencyOptions {
  useNepaliDigits?: boolean
  showPaisa?: boolean         // show paisa portion separately
  currencySymbol?: string     // default "रू"
  precision?: number
}
```

### Utils (`src/utils/`)

| Function | Signature | Description |
|---|---|---|
| `normalize` | `(input: string) => string` | Trim, collapse spaces/commas/decimals; use before parsing |
| `detectNumberSystem` | `(input: string) => NumberSystem \| typeof NaN` | Returns `"english"`, `"nepali"`, `"mixed"`, or `NaN` |
| `validateNepaliNumber` | `(input: string) => boolean` | True if string is a valid Nepali number |
| `isNepaliDigit` | `(char: string) => boolean` | True if single char is ०-९ |
| `isEnglishDigit` | `(char: string) => boolean` | True if single char is 0-9 |
| `isMixedNumber` | `(input: string) => boolean` | True if contains both digit types |
| `padZeros` | `(input: string, length: number) => string` | Pad with Nepali zeros (०) to reach target length |
| `roundNepali` | `(input: string \| number, precision: number) => string` | Round and return with Nepali digits |

**`NumberSystem`** (from `src/utils/types.ts`): `"english" | "nepali" | "mixed"`

## Constants (`src/constants.ts`)

The single source of truth for all language data. Do not hardcode Nepali strings in domain modules — reference these constants instead.

| Export | Type | Description |
|---|---|---|
| `NEPALI_DIGITS` | `string` | `"०१२३४५६७८९"` — index by English digit to get Nepali equivalent |
| `NEPALI_SCALES` | `array` | 10 scale objects: महाशंख → सय (10^19 down to 10^2), each with Nepali/English labels and ordinals |
| `NEPALI_WORDS` | `array` | 100 Nepali cardinal word strings, indexed 0–99 |
| `NEPALI_ORDINALS_EXCEPTIONS` | `object` | Irregular ordinals for 0–4 (पहिलो, दोस्रो, etc.) |
| `NEPALI_ORDINALS` | `array` | 100 Nepali ordinal word strings, indexed 0–99 |
| `ENGLISH_WORDS` | `object` | `{ ONES, TEENS, TENS }` arrays for English word generation |

When adding new word tables or digit mappings, add them here — not inline in domain files.

## Adding a New Function

Follow these exact steps in order:

### Step 1 — Decide the domain
Place the function in the most semantically fitting domain folder. If no existing domain fits, create a new one (see "Adding a New Domain" below).

### Step 2 — Implement
In the domain's `*.ts` file, write the function with:
- A verb-led name: `toNepaliX`, `formatX`, `addX`, `removeX`, `parseX`, `detectX`
- An explicit return type
- No thrown errors — return a safe default on invalid input
- Input normalization at the top: call `normalize()` from `@/utils` before any parsing
- Cross-domain parsing via `parseNepaliNumber()` from `@/conversion` when you need a JS number

```ts
// Example skeleton
export const toNepaliXyz = (input: string | number): string => {
  const normalized = normalize(String(input))
  if (!normalized) return ""
  // ... implementation using constants, not hardcoded strings
  return result
}
```

### Step 3 — Add types if needed
If the function takes an options object, define an interface in the domain's `types.ts` and export it.

### Step 4 — Re-export
Add the function to the domain's `index.ts`:
```ts
export { toNepaliXyz } from "./myfile"
```
The barrel `src/nepali-number.ts` already does `export * from "@/domain"`, so no change there is needed unless you're adding a new domain.

### Step 5 — Write tests
Create or extend `*.test.ts` in the same domain folder. Every exported function needs tests covering:
- Typical positive input (English digits, Nepali digits)
- Empty string / zero / null-ish input
- Negative numbers
- Decimal numbers
- Mixed English/Nepali digit input
- Large numbers (≥ 1 crore)
- Boundary values specific to the function

### Step 6 — Validate
Run all three checks before marking work done:
```bash
bun run type-check   # must pass with zero errors
bun run test         # must pass with full coverage
bun run build        # must succeed and emit dist/
```

## Adding a New Domain

Only when no existing domain fits semantically:

1. Create `src/<domain>/` folder
2. Add `<domain>.ts` — implementation
3. Add `types.ts` — interfaces/types (if any)
4. Add `index.ts` — re-exports from `<domain>.ts` and `types.ts`
5. Add `<domain>.test.ts` — tests
6. Add `export * from "@/<domain>"` to `src/nepali-number.ts`

## Testing Patterns

**Test runner**: Bun (`bun test`). Import from `"bun:test"`.

```ts
import { describe, test, expect } from "bun:test"
import { myFunction } from "./myfile"

describe("myFunction", () => {
  test("converts English digits", () => {
    expect(myFunction("123")).toBe("expected")
  })

  test("handles empty input", () => {
    expect(myFunction("")).toBe("")
  })

  test("handles Nepali digits", () => {
    expect(myFunction("१२३")).toBe("expected")
  })
})
```

Coverage is always collected (configured in `bunfig.toml`). The coverage threshold is not currently enforced by config, but aim for complete branch coverage on all public functions.

## TypeScript Constraints

The `tsconfig.json` enforces the following flags that commonly trip up agents:

- **`noUnusedLocals` / `noUnusedParameters`**: Every declared variable and parameter must be used. Remove unused ones rather than prefixing with `_` unless the parameter is required by a callback signature.
- **`noUncheckedIndexedAccess`**: Array/object index access returns `T | undefined`. Always guard or use non-null assertion with a comment explaining why it's safe.
- **`isolatedDeclarations`**: All exported functions must have explicit return types — TypeScript cannot infer them from cross-file references. Do not rely on inference for public APIs.
- **`strictNullChecks`**: Enabled. Handle `null` and `undefined` explicitly.
- **`noImplicitOverride`**: Use `override` keyword explicitly when overriding in classes (rare in this codebase).

## Common Pitfalls

| Pitfall | Correct approach |
|---|---|
| Hardcoding `"०"`, `"१"`, etc. in domain files | Use `NEPALI_DIGITS[n]` from `@/constants` |
| `input.length` on a Nepali string | `Array.from(input).length` or `.replace()` with regex |
| Calling `parseInt()` on Nepali input | Call `parseNepaliNumber()` first, then work with the JS number |
| Using `console.log` in library code | Remove before committing; debug only in test files |
| Importing a domain from another domain | Route through shared `@/utils` or `@/constants` only |
| Adding a function without a test | Every exported function needs a `*.test.ts` entry |
| Omitting the return type on an exported function | Always explicit — required by `isolatedDeclarations` |
| Adding an options parameter without a `types.ts` entry | Define the interface in `types.ts` and export it |
